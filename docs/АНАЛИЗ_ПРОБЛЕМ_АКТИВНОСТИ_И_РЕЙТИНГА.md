# 🔍 Анализ проблем записи активности и расчета рейтинга

## 📊 Анализ данных из БД

### Структура таблицы `ai_signals`
- ✅ Есть поля `mood_rating`, `energy_rating`, `stress_rating` (но они **NULL** в записях активности)
- ✅ Есть поля `activity_category`, `duration_minutes`, `success_rating`, `quality_score`, `notes`
- ✅ Есть JSONB поле `data` с полными данными активности

### Реальные записи активности (user_id = 3)
```
id=202: activity_category='health', duration_minutes=135, success_rating=8, quality_score=0.90
id=200: activity_category='health', duration_minutes=120, success_rating=9, quality_score=1.00
```
- ❌ `mood_rating`, `energy_rating`, `stress_rating` = **NULL** (не заполняются)
- ✅ Данные есть в JSONB: `{"activity": "...", "category": "...", "duration": ..., "success": true}`

## 🚨 КРИТИЧЕСКИЕ ПРОБЛЕМЫ И НЕСООТВЕТСТВИЯ

### Проблема 1: Функция использует NULL поля

**Функция `calculate_productivity_score`:**
```sql
-- Ищет записи настроения
SELECT COALESCE(SUM(mood_rating + energy_rating + (10 - stress_rating)), 0)
FROM ai_signals 
WHERE type IN ('mood', 'daily_mood_check')
```

**Проблема:** 
- Для записей активности (`type='activity'`) поля `mood_rating`, `energy_rating`, `stress_rating` = **NULL**
- Функция НЕ использует эти поля для активности, но они есть в структуре
- Данные активности хранятся в JSONB, но функция их **НЕ извлекает**

### Проблема 2: Несоответствие типов записей

**В функции:**
```sql
WHERE type IN ('activity', 'activity_analysis')
```

**В реальных данных:**
- Записи имеют `type='activity'` ✅
- Но в коде API (`api/productivity.js`) сохраняется как `type='activity_analysis'` ❌

**Несоответствие:**
- `/api/ai/log-activity` сохраняет `type='activity'` ✅
- `/api/productivity/activity-log` сохраняет `type='activity_analysis'` ❌
- Функция ищет оба типа, но это может привести к дублированию

### Проблема 3: Данные в JSONB не используются

**Что сохраняется в JSONB:**
```json
{
  "activity": "Тренировка в зале",
  "category": "health", 
  "duration": 120,
  "success": true,
  "notes": "...",
  "timestamp": "..."
}
```

**Что использует функция:**
- Использует поля напрямую: `activity_category`, `duration_minutes`, `success_rating`
- **НЕ извлекает данные из JSONB** - дублирование данных

### Проблема 4: Функция get_user_productivity_stats неполная

**Что возвращает:**
```sql
RETURNS TABLE(
    overall_rating numeric, 
    total_records integer, 
    mood_average numeric, 
    activity_average numeric
)
```

**Что ожидает код:**
```javascript
stats.rows[0]?.overall_rating
stats.rows[0]?.total_records
stats.rows[0]?.mood_stability      // ❌ НЕТ в функции!
stats.rows[0]?.energy_consistency // ❌ НЕТ в функции!
stats.rows[0]?.stress_management  // ❌ НЕТ в функции!
stats.rows[0]?.xp_multiplier      // ❌ НЕТ в функции!
stats.rows[0]?.total_achievements  // ❌ НЕТ в функции!
```

**Результат:** Код обращается к несуществующим полям → получает `undefined`

### Проблема 5: Расчет рейтинга не учитывает качество описания

**Что есть:**
- `quality_score` рассчитывается на основе длины `notes`:
  - ≥30 символов → 1.0
  - ≥20 символов → 0.8
  - ≥10 символов → 0.6
  - <10 символов → 0.4

**Что использует функция:**
- `quality_score` сохраняется в БД ✅
- Но функция `calculate_productivity_score` **НЕ использует** `quality_score` в расчетах ❌

### Проблема 6: Недельные/месячные рейтинги не рассчитываются

**В коде:**
```javascript
weekly_rating: stats.rows[0]?.overall_rating || 0,  // Просто копирует
monthly_rating: stats.rows[0]?.overall_rating || 0, // Просто копирует
```

**Ожидаемое поведение:**
- `weekly_rating` = средний рейтинг за последние 7 дней
- `monthly_rating` = средний рейтинг за последние 30 дней

```sql
CREATE FUNCTION calculate_weekly_rating(p_user_id INTEGER)
RETURNS NUMERIC AS $$
    SELECT AVG(final_score)
    FROM productivity_scores
    WHERE user_id = p_user_id
    AND date >= CURRENT_DATE - INTERVAL '7 days';
$$;

CREATE FUNCTION calculate_monthly_rating(p_user_id INTEGER)
RETURNS NUMERIC AS $$
    SELECT AVG(final_score)
    FROM productivity_scores
    WHERE user_id = p_user_id
    AND date >= CURRENT_DATE - INTERVAL '30 days';
$$;
```
