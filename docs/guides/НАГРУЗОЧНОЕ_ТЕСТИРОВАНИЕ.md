# Нагрузочное тестирование Yoddle

Цель: проверить, что платформа выдерживает **100 одновременных пользователей** без падений и с приемлемым временем ответа.

---

## Быстрый старт (Ubuntu + k6)

1. **Установить k6 на Ubuntu:**
   ```bash
   sudo gpg -k
   sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D6
   echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
   sudo apt-get update
   sudo apt-get install k6
   k6 version
   ```

2. **Запустить сервер** (в одном терминале):
   ```bash
   cd /path/to/yoddle
   npm run server
   ```
   Сервер слушает порт **3001**.

3. **Запустить нагрузочный тест** (в другом терминале):
   ```bash
   cd /path/to/yoddle/scripts/load
   k6 run --vus 100 --duration 60s k6-load-100.js
   ```
   Если k6 установлен локально в проект (папка `scripts/load/bin/`), используйте:
   ```bash
   cd /path/to/yoddle/scripts/load
   ./bin/k6 run --vus 100 --duration 60s k6-load-100.js
   ```

4. В выводе смотреть: **RPS**, **http_req_duration (avg, p95)**, **http_req_failed**. Сохранить вывод в файл при необходимости:  
   `k6 run --vus 100 --duration 60s k6-load-100.js 2>&1 | tee load-test-100.txt`

## Если приложение запущено в Docker

В проекте бэкенд в Docker пробрасывает порт **3001** на хост (`docker-compose.yml`: `backend` → `3001:3001`).

### Вариант A: k6 на хосте (рекомендуется)

Запускаете k6 **на своей машине**, а не в контейнере. API доступен по `localhost:3001`, потому что порт проброшен.

1. Запустите контейнеры: `docker compose up -d` (или `docker-compose up -d`).
2. Убедитесь, что бэкенд отвечает: `curl http://localhost:3001/health`.
3. Запустите тест (k6 на хосте):
   ```bash
   cd scripts/load
   ./bin/k6 run --vus 100 --duration 60s k6-load-100.js
   ```
   По умолчанию скрипт использует `BASE_URL=http://localhost:3001` — менять ничего не нужно.

### Вариант B: k6 в Docker (в той же сети, что и backend)

Если хотите гонять нагрузку из контейнера, можно запустить k6 в Docker и стучаться в сервис по имени `backend`:

```bash
docker run --rm -i --network yoddle_yoddle-network \
  -v "$(pwd)/scripts/load:/scripts" \
  grafana/k6 run \
  --vus 100 --duration 60s \
  -e BASE_URL=http://backend:3001 \
  /scripts/k6-load-100.js
```

Запускать из **корня проекта** (`$(pwd)` должен быть путём к репозиторию yoddle). Имя сети обычно `yoddle_yoddle-network` (префикс от имени папки); проверьте: `docker network ls | grep yoddle`.

## Тест против удалённого сервера

Если API крутится на **другой машине** (VPS, прод, другой хост), k6 можно запускать у себя на компьютере и гнать нагрузку на этот сервер. Меняется только базовый URL.

1. Убедитесь, что с вашей машины доступен сервер (в браузере или `curl`):
   ```bash
   curl https://your-server.com/health
   ```
   Подставьте ваш домен или IP (и порт, если не 80/443), например: `https://api.yoddle.ru`, `http://192.168.1.10:3001`.

2. Запустите тест, передав URL через переменную **BASE_URL**:
   ```bash
   cd scripts/load
   ./bin/k6 run --vus 100 --duration 60s -e BASE_URL=https://your-server.com k6-load-100.js
   ```
   Примеры:
   - `-e BASE_URL=https://api.yoddle.ru`
   - `-e BASE_URL=http://123.45.67.89:3001`
   - `-e BASE_URL=https://yoddle.example.com` (если API за nginx на 443)

3. Результат смотрите в терминале (RPS, время ответа, ошибки). Сохранить вывод в файл:
   ```bash
   ./bin/k6 run --vus 100 --duration 60s -e BASE_URL=https://your-server.com k6-load-100.js 2>&1 | tee load-test-server.txt
   ```

**Важно:** На проде лучше сначала гонять меньшую нагрузку (например `--vus 10 --duration 30s`), потом поднимать. Убедитесь, что нагрузочное тестирование сервера не нарушает правил хостинга.

---

## Что измеряем

| Метрика | Цель для пилота |
|--------|------------------|
| Время ответа (p95) | < 2 сек для основных страниц/API |
| Ошибки | 0% (или < 0.1%) |
| RPS (запросов в сек) | Уметь обрабатывать пики до ~50–100 RPS |
| Стабильность | Сервер и БД не падают под нагрузкой |

## Вариант 1: k6 (рекомендуется)

**k6** — бесплатный инструмент от Grafana Labs, один бинарник, сценарии на JavaScript.

### Установка k6

**Linux (Debian/Ubuntu):**
```bash
sudo gpg -k
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D6
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update
sudo apt-get install k6
```

**macOS:**
```bash
brew install k6
```

**Проверка:**
```bash
k6 version
```

### Запуск теста на 100 пользователей

1. Запустите приложение (сервер и, при необходимости, фронт):
   ```bash
   npm run server
   ```
   По умолчанию API на порту **3001** (разработка).

2. В другом терминале выполните:
   ```bash
   cd scripts/load
   k6 run --vus 100 --duration 60s k6-load-100.js
   ```
   - `--vus 100` — 100 виртуальных пользователей  
   - `--duration 60s` — тест 60 секунд  
   - Базовый URL по умолчанию: `http://localhost:3001` (можно задать через `--env BASE_URL=http://your-server:3001`).

3. Итог в терминале: количество запросов, RPS, время ответа (avg, p95, p99), процент ошибок.

### Параметры сценария

- В `k6-load-100.js` заложены типичные запросы: health, login, progress, benefits, activity. При необходимости отредактируйте файл (добавьте свои маршруты).
- Для «плавного» выхода нагрузки:
  ```bash
  k6 run --vus 100 --duration 120s --ramp-up 30s k6-load-100.js
  ```
  Первые 30 секунд пользователи подключаются постепенно.

## Вариант 3: Простой скрипт на Node.js (без k6/Artillery)

Если не хотите ставить k6 или Artillery, можно гонять параллельные запросы своим скриптом:

```bash
node scripts/load/simple-load.js
```

Скрипт делает N параллельных запросов к основным API и выводит время ответа и ошибки. Удобно для быстрой проверки «держит ли вообще».

---

## Что тестировать в первую очередь

1. **GET /api/benefits** — каталог льгот (часто открывают).  
2. **GET /api/progress?user_id=…** — прогресс (дашборд).  
3. **GET /api/user-benefits?user_id=…** — мои льготы.  
4. **GET /api/activity?user_id=…** — активность (график).  
5. **POST /api/login** — вход (пиковая нагрузка в начале дня).  
6. **GET /health** — проверка живости сервера.

Сценарий k6 в `scripts/load/k6-load-100.js` уже использует часть этих маршрутов; остальные можно добавить по аналогии.

---

## Интерпретация результатов

- **Ошибки (http_req_failed)** — если > 0%, ищите таймауты, 5xx, падения БД.  
- **p95 > 2 сек** — оптимизировать тяжёлые запросы или БД (индексы, пул соединений).  
- **Рост времени ответа к концу теста** — возможны утечки памяти или исчерпание пула БД.

После прогона сохраните вывод k6/Artillery в файл (например, `load-test-100-2026-02-02.txt`) для отчёта.
