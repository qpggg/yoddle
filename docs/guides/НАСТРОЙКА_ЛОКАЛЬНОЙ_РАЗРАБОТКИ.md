# 🛠️ Настройка локальной разработки с удаленной БД

## 📋 Обзор

Это руководство поможет настроить локальную среду разработки для работы с базой данных на сервере. Все изменения в коде будут синхронизироваться с удаленной БД в реальном времени.

## ⚙️ Требования

- Node.js >= 20.0.0
- npm или yarn
- Доступ к удаленной БД (хост, порт, имя БД, пользователь, пароль)
- API ключи для сервисов (Claude AI, Resend и т.д.)

## 🔧 Шаг 1: Установка зависимостей

```bash
cd /home/bachira/Документы/yoddle
npm install
```

## 🔐 Шаг 2: Настройка переменных окружения

### 2.1. Создание файла `.env`

Скопируйте шаблон:
```bash
cp .env.example .env
```

### 2.2. Настройка подключения к БД

Откройте `.env` и настройте подключение к удаленной БД. Есть два способа:

#### Способ 1: Полная строка подключения (рекомендуется)

```env
# Подключение к удаленной БД на сервере
PG_CONNECTION_STRING=postgresql://username:password@host:port/database

# Пример для Supabase:
# PG_CONNECTION_STRING=postgresql://postgres.xxxxx:password@aws-0-eu-north-1.pooler.supabase.com:5432/postgres?sslmode=require

# Пример для обычного PostgreSQL:
# PG_CONNECTION_STRING=postgresql://yoddle_user:password@your-server.com:5432/yoddle_db
```

#### Способ 2: Отдельные переменные

```env
PGHOST=your-server.com
PGPORT=5432
PGDATABASE=yoddle_db
PGUSER=yoddle_user
PGPASSWORD=your_password
```

**Важно:** Если используется Supabase или требуется SSL, добавьте `?sslmode=require` в строку подключения.

### 2.3. Настройка остальных переменных

```env
# Сервер
PORT=3001
NODE_ENV=development

# Claude AI (обязательно для AI функций)
CLAUDE_API_KEY=your_claude_api_key_here
CLAUDE_BASE_URL=https://anthropic-proxy.yoddle-proxy.workers.dev

# Resend (для отправки email)
RESEND_API_KEY=your_resend_api_key_here

# JWT секрет (для токенов авторизации)
JWT_SECRET=your_jwt_secret_here

# Telegram Bot (опционально, если используете бота)
BOT_TOKEN=your_telegram_bot_token
ADMIN_CHAT_ID=your_telegram_id

# API URLs
API_BASE_URL=http://localhost:3001
YODDLE_WEB_URL=http://localhost:5173
```

## ✅ Шаг 3: Проверка подключения к БД

Запустите скрипт проверки:
```bash

```

Или используйте утилиту:
```bash
node scripts/utils/check_db_connection.js
```

Вы должны увидеть:
```
✅ Подключение к БД успешно!
📊 Информация о БД:
   Host: your-server.com
   Database: yoddle_db
   User: yoddle_user
```

## 🚀 Шаг 4: Запуск проекта

### Запуск фронтенда (в одном терминале)
```bash
npm run dev
```
Фронтенд будет доступен на `http://localhost:5173`

### Запуск бэкенда (в другом терминале)
```bash

```
Бэкенд будет доступен на `http://localhost:3001`

### Или запуск обоих одновременно
```bash

npm run dev:server
```

## 🐛 Решение проблем

### Ошибка: "PG_CONNECTION_STRING is not set"

**Решение:** Убедитесь, что файл `.env` существует и содержит `PG_CONNECTION_STRING` или отдельные переменные `PGHOST`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`.

### Ошибка: "Connection refused" или "timeout"

**Возможные причины:**
1. БД недоступна с вашего IP (нужно добавить в whitelist)
2. Неправильный хост или порт
3. Проблемы с SSL (для Supabase добавьте `?sslmode=require`)

**Решение:**
- Проверьте доступность БД: `ping your-server.com`
- Проверьте порт: `telnet your-server.com 5432`
- Для Supabase проверьте настройки в панели управления

### Ошибка: "password authentication failed"

**Решение:** Проверьте правильность пароля в `.env`. Убедитесь, что пароль не содержит специальных символов, которые нужно экранировать в URL.

### Ошибка: "CLAUDE_API_KEY не установлен"

**Решение:** Добавьте `CLAUDE_API_KEY` в `.env`. AI функции не будут работать без этого ключа.

## 📝 Важные замечания

1. **Безопасность:**
   - Никогда не коммитьте файл `.env` в Git
   - Используйте `.env.example` как шаблон
   - Храните реальные ключи в безопасном месте

2. **Синхронизация с продакшеном:**
   - Все изменения в коде будут применяться к удаленной БД
   - Будьте осторожны при тестировании деструктивных операций
   - Используйте транзакции для тестовых данных

3. **Производительность:**
   - Работа с удаленной БД может быть медленнее локальной
   - Используйте пул соединений (уже настроен в `db.js`)
   - При необходимости можно настроить локальную БД для разработки

## 🔄 Переключение между локальной и удаленной БД

Если нужно переключиться на локальную БД:

1. Установите PostgreSQL локально
2. Создайте БД и пользователя
3. Обновите `.env`:
   ```env
   PG_CONNECTION_STRING=postgresql://yoddle_user:password@localhost:5432/yoddle_db
   ```
4. Запустите миграции из `scripts/sql/`
