### 3. Проработка финансовой и учётной модели

- **Поток оплаты при интеграции:**
  - Компания (клиент Yoddle) платит: подписку за платформу + бюджет на льготы (пул монет для сотрудников)
  - При списании монет сотрудником за льготу: бэкенд дергает API партнёра → партнёр выдаёт продукт → оплата за выдачу идёт партнёру (из бюджета, переведённого компанией, или по схеме партнёра — предоплата/постоплата)

- **Разделение выручки (чтобы не смешивать):**
  - Подписка — выручка Yoddle (оказание услуг по договору)
  - Бюджет на льготы — проходные деньги (агентская схема): либо не считать выручкой, а учитывать только маржу/комиссию как выручку; либо вести отдельно выручку по бенефитам и расход партнёру, чтобы в прибыли оставалась только разница
  - В договоре с компанией зафиксировать два пункта: вознаграждение за подписку и целевые средства на приобретение бенефитов

- **Возможность комиссии от партнёра:**
  - Запланировано уточнить на консультации: есть ли партнёрская/агентская программа, готовы ли платить процент от оборота по льготам, идущего через Yoddle; тогда выручка от льгот = их комиссия, без смешивания с проходным бюджетом

### 4. Планирование технической стороны интеграции и пилота

- **Технический сценарий (после договорённости):**

  - Оплата партнёру: по согласованной схеме (предоплата пула, постоплата по актам и т.д.)

- **Достаточность для пилота:**

  - Детали (вебхуки, массовая выдача, отчёты) — после проверки спроса

### 5. Страница прогресса и геймификация (XP)

- **Тесты базовых XP (curl + БД):**
  - Ограничение «просмотр прогресса — раз в день»: первый вызов `progress_view`/`page_view` даёт +5 XP, повтор в тот же день — 0 XP, в `activity_log` запись с `xp_earned = 0`. Работает.
  - Ограничение «загрузка аватара — раз в неделю»: первый вызов за 7 дней — +30 XP, повтор в ту же неделю — 0 XP. Работает.
  - Остальные действия (логин, profile_update, benefit_added, benefit_used) начисляют XP по спецификации.
  - В ответе POST /api/activity добавлено поле `xpAwarded` для проверки фактически начисленного XP.
- **Сверка:** сумма по `activity_log.xp_earned` совпадает с ожидаемой за прогон; ограничения соблюдены. Страница прогресса отображает уровень, XP, достижения, статистику; начисление за просмотр идёт через API с ограничением «раз в день».
- **Итог:** геймификация и страница прогресса работоспособны, вопрос закрыт. Команды для повторного прогона — в `docs/ТЕСТЫ_БАЗОВЫХ_XP_ДЕЙСТВИЙ.md`, отчёт тестов — `docs/ОТЧЕТ_ТЕСТОВ_XP_29.01.2026.md`.
