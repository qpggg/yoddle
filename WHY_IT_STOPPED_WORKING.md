# 🤔 ПОЧЕМУ ПРИЛОЖЕНИЕ РАБОТАЛО РАНЬШЕ, А СЕЙЧАС НЕТ?

## 📅 ЧТО ИЗМЕНИЛОСЬ СЕГОДНЯ:

### 1. **Переименование конфига PM2**
- **Было:** `ecosystem.config.js`
- **Стало:** `ecosystem.config.cjs` (из-за `"type": "module"` в package.json)
- **Проблема:** PM2 не может загрузить старый `.js` файл, ищет новый `.cjs`

### 2. **Изменение порта в конфиге**
- **Было:** Возможно, порт был 3000 или приложение запускалось без конфига
- **Стало:** Порт 3001 в `ecosystem.config.cjs`
- **Проблема:** Конфликт с nginx, который слушает на 3001

### 3. **Добавление параметров PM2**
- Добавлены `wait_ready`, `listen_timeout`, `kill_timeout`
- **Проблема:** PM2 теперь ждет сигнал `ready`, но приложение не может запуститься из-за занятого порта

### 4. **Nginx слушает на порту 3001**
- **Это неправильно!** Nginx должен слушать на 80/443 и проксировать на 3001
- **Вопрос:** Почему nginx слушает на 3001? Возможно:
  - Конфигурация nginx была изменена
  - Или раньше приложение работало на другом порту (3000)
  - Или раньше nginx был настроен правильно

## 🔍 ВОЗМОЖНЫЕ СЦЕНАРИИ РАНЬШЕ:

### Сценарий 1: Приложение работало на порту 3000
```bash
# Раньше могло быть:
PORT=3000 в .env
# или
pm2 start server.js --name yoddle-api
# без указания порта (использовался дефолт 3000)
```

### Сценарий 2: Nginx был настроен правильно
```nginx
# Раньше nginx мог быть настроен так:
server {
    listen 80;  # Правильно!
    location / {
        proxy_pass http://localhost:3000;  # Проксировал на 3000
    }
}
```

### Сценарий 3: Приложение запускалось до nginx
- Если приложение запускалось первым, оно занимало порт 3001
- Nginx не мог запуститься на 3001 (или был настроен правильно)

## ✅ ЧТО НУЖНО СДЕЛАТЬ:

### Вариант 1: Исправить nginx (рекомендуется)
```bash
# 1. Проверьте конфиг nginx
cat /etc/nginx/sites-enabled/yoddle

# 2. Убедитесь, что нет "listen 3001;"
# Должно быть: "listen 80;" и "listen 443 ssl;"

# 3. Исправьте конфиг
nano /etc/nginx/sites-enabled/yoddle

# 4. Перезагрузите nginx
systemctl reload nginx

# 5. Убейте процессы nginx на 3001
kill -9 712 713 714

# 6. Запустите приложение
cd /root/yoddle
pm2 start ecosystem.config.cjs
```

### Вариант 2: Вернуться к порту 3000
```bash
# 1. Измените порт в ecosystem.config.cjs на 3000
nano ecosystem.config.cjs
# PORT: 3000

# 2. Измените порт в .env на 3000
nano .env
# PORT=3000

# 3. Обновите nginx конфиг (если нужно)
nano /etc/nginx/sites-enabled/yoddle
# proxy_pass http://localhost:3000;

# 4. Перезагрузите nginx
systemctl reload nginx

# 5. Запустите приложение
pm2 start ecosystem.config.cjs
```

## 🎯 РЕКОМЕНДАЦИЯ:

**Исправьте nginx** - это правильная архитектура:
- Nginx на 80/443 (публичный доступ)
- Node.js на 3001 (внутренний порт)
- Nginx проксирует запросы

Это стандартная и правильная конфигурация для production.
